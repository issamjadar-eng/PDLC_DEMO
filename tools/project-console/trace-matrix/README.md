# `tools/project-console/trace-matrix/` — project-side adapters for the trace-matrix skill

This directory holds **project-specific generated code** for the `trace-matrix` skill. It is owned by the project, not the skill. Everything under `adapters/` is either committed by the team or generated by `/trace-matrix init`.

## What's in here

| Path | Written by | Purpose |
|---|---|---|
| `adapters/<layer>.py` | `/trace-matrix init` or the team | Overrides the default parser shipped in the skill. Present → used at build time. Absent → skill default is used. |
| `analysis-notes.md` | `/trace-matrix init` | Human-readable record of what the init analyzer saw in each source doc and why each adapter was (or was not) generated. |

## How the override resolver works

When `/trace-matrix build` runs, for each layer it looks up the adapter in this order:

1. **`tools/project-console/trace-matrix/adapters/<layer>.py`** — project override
2. **`.claude/skills/trace-matrix/scripts/parsers/defaults/<layer>.py`** — skill default

Both expose the same `parse(path, layer_cfg) -> ParserResult` function. The build is always deterministic; no LLM runs at build time.

## When does the skill generate an adapter?

Only during `/trace-matrix init`. The flow:

1. The skill reads `trace-matrix.yml` and enumerates each (DHF × layer).
2. For each pair, it runs the default parser and validates the output via a "rational check" — do the returned IDs plausibly match the configured prefix, are there nodes, is the source present, etc.
3. If the check passes, no adapter is generated.
4. If the check fails **and** the source document has content (i.e. it's a parser problem, not a data gap), the skill reads the source and generates a per-project adapter here, with a rationale header explaining the decision.

## Regenerating

- **Single layer**: `/trace-matrix init --regenerate --dhf <name> --layer <key>`
- **Single DHF**: `/trace-matrix init --regenerate --dhf <name>`
- **Everything**: `/trace-matrix init --regenerate`

## Editing by hand

These files are plain Python. If the generated adapter is *almost* right but needs a tweak, edit it directly and commit the change. The skill will not overwrite a file unless `--regenerate` is passed.

## Conventions

- Adapters must be deterministic (no LLM calls, no network).
- Each adapter's module docstring should capture the source doc's shape and the rationale for why defaults didn't fit.
- Prefer stdlib-only regex parsing; avoid adding dependencies.
- Return `ParserResult(nodes, warnings, extras)`. Warnings are non-fatal — they surface in build stdout and in the generated deliverable.
