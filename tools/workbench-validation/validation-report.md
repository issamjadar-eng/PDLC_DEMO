- **Untested deterministic checkers** — several load-bearing lint/checker scripts have no regression suite pinning their behavior (regulatory-authoring `authoring_lint.py`, submissions linters, commercial `dossier_lint.py`, gap-analysis sidecar renderer). WUN-04 evidence rests on the writing-well lint suite only. Owner: each skill's maintainer. Expected to clear: one case per checker added as suites land; the secops scanner closed its own instance of this gap in 2026-09 (TC-19).
- **Suite exit-code masking** — the task-gate suite reports per-scenario failures but exits 0 regardless; pass/fail is derived from its output banner (`pass_pattern`). Owner: task skill maintainer. Expected to clear: the run after the suite exits non-zero on any failed scenario.
- **Environment sensitivity** — the task-gate suite requires `CLAUDE_SESSION_ID` to be unset (a live agent session's ID makes fake-session DENY scenarios resolve ALLOW); the runner strips it via `env_unset` and records it in the environment record's isolation block. Accepted residual: documented, mechanically enforced by the manifest.
- **Model identifier depends on the operator** — the harness does not export the model to scripts; the runner records it only when passed via `--model-id` (or `$CLAUDE_MODEL`) and otherwise reports 'not captured' as a run warning. Owner: validation operator (record at run time). Accepted residual until the harness exposes it.
- **Live-endpoint cases are NOT-APPLICABLE here by declaration** — `connections:` declares jira / confluence / browser as `none`; TC-17/18/21 therefore never execute in this deployment and WUN-16 is exploratory. Not a gap for this project; a deployment with a connection flips the declaration and the same cases run live.

**LLM non-determinism.** LLM-driven skill behavior (content generation, judgment, advisory output) is **not repeatably testable** and is deliberately excluded from scripted pass/fail claims in this report. Those needs are assured through process controls — mandatory human review before content enters the controlled record, deterministic gates (hooks, lints, renderers) wrapped around the non-deterministic core, grounding rules, and the git/PR audit trail — and are labeled PROCESS-CONTROL or EXPLORATORY, never PASS. A change of the underlying model is a first-class revalidation trigger because it changes tool behavior with zero repository diff.
