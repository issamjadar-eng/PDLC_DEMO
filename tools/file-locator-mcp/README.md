# file-locator MCP — installed instance

This directory holds the project's installed copy of the file-locator MCP. The
actual server, indexer, and config live in `.claude/skills/file-locator/` (the
registry-tracked skill); this directory only holds **the committed index** plus
a convenience rebuild script.

## Files in this directory

| File | Purpose | Origin |
|---|---|---|
| `index.db` | The SQLite index. **Committed.** Contains: `indexed_files` state table (path, content_hash, mtime, indexed_at), `summaries` table (file-level + sub-summaries with embeddings), FTS5 virtual table for BM25, `metadata` table (embedding model, schema version). | Generated by `/file-locator rebuild` |
| `rebuild.sh` | Convenience wrapper around the skill's `rebuild.py`. Run from anywhere in the repo. | Installed by `/file-locator setup` |
| `requirements.txt` | Pinned Python deps (`fastembed`, `mcp`, `pyyaml`). | Installed by `/file-locator setup` |
| `README.md` | This file. | Installed by `/file-locator setup` |

## Rebuild

```bash
# Incremental (only changed files re-processed)
bash tools/file-locator-mcp/rebuild.sh

# Full rebuild from scratch
bash tools/file-locator-mcp/rebuild.sh --full
```

A no-op rebuild (when nothing has changed) is genuinely a no-op — just hash
comparisons. A rebuild after editing one doc is ~one embedding call.

## Ownership

The team's canonical `index.db` advances through CI on PR merge. Local rebuilds
are a session-local refresh — handy when you need fresher data than CI has
produced, but the next `git pull` will overwrite your local index with CI's.

For maintenance rebuilds where you want to commit:

```bash
bash tools/file-locator-mcp/rebuild.sh
git add tools/file-locator-mcp/index.db
git commit -m "file-locator: rebuild index"
```

## What this server does — and doesn't

**Does:** semantic file-level search. Given a query, returns ranked
`(path, summary, heading_anchor?, score)` tuples banded by confidence.

**Doesn't:** chunked passage retrieval, full-text search of doc bodies (the
index only stores summaries — never raw doc content), code search (v1 is
docs-only; `scope=code` returns an empty result + reasoning hint).

## What gets indexed

See `project.yml file_locator.corpus_includes` and `corpus_excludes`. Run
`/file-locator audit` to see what each gate filters and why.

## Network posture

The server runs over **stdio only**, no listening sockets. Verify with
`lsof -p <pid>` while it's running. No outbound network calls during indexing
or query — the embedding model runs locally via ONNX.
