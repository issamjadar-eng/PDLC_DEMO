## Question

For each roadmap feature: documented KOL evidence on file? Which ride on a single
voice, and does current sentiment still order the waves?

**Asked by**: vp-product · **cadence**: annual

## Goal — the decision this answer serves

The annual evidence audit behind the F1–F9 roadmap: which features have sufficient
documented KOL backing, which ride on a single voice, and whether the sentiment on file
still supports the wave ordering — the input to commissioning real KOL engagement
before the next roadmap commit.

**The epistemic status of the register is the headline, not a footnote**: every current
row is a simulated advisory-panel opinion; zero real collected KOL evidence exists.
The answer must lead with that meta-gap before any per-feature arithmetic.

## Approach

Operational definitions this answer commits to:

- **Feature universe** = F1–F9 from config `feature_universe` (commercial-strategy.md
  D-COMM-1.4) — every feature is evaluated even if it has zero register rows; a zero is
  a finding, not an omission.
- **Voices** = count of **distinct kol_id** per feature in the pinned register.
  **Single-voice feature** = exactly one distinct voice.
- **Sentiment mix** = per-feature counts of `support` / `neutral` / `concern` rows;
  **concern-majority** = concern rows strictly greater than support + neutral combined.
- **E-16.1 evaluation** = every feature in the universe has ≥ 2 distinct voices; one
  failure fails the expectation.
- **Wave check** (deterministic): a concern-majority feature whose `feature_years` slot
  is Y2–Y4 is flagged "no documented slot endorsement" — an **evidence-absence**
  reading (concern-majority ≠ documented endorsement of the slot), NOT a claim that
  the panel opposes the slot. Advisory, because of the meta-gap below.
- **Vocabulary-flattening limitation** (red-team RT-16.1, stated in the answer): the
  register's 3-value sentiment scale (support | neutral | concern) cannot carry the
  *direction or conditionality* of a concern — per the dataset README convention, a
  "conditional yes" encodes as `concern`. Source-doc spot checks confirm flagged-slot
  concern voices that explicitly endorse the sequencing while demanding conditions
  (Giuliano/F4, Gorski/F7). The answer must not read concern-majority as slot
  opposition; a stance (support/conditional/oppose) × timing (earlier/as-scheduled/
  later) split is the recommended register upgrade when real evidence is collected.
- **Meta-gap** = evidence-type census: rows by `evidence_type`; the register currently
  contains only `advisory-board` rows from the simulated 8-persona panel (dataset
  README, review finding F-1) — `interview` / `survey` / `publication` counts are zero.
  Every sentiment-based statement in the answer carries this caveat.

## Assumptions & expectations

- **E-16.1** — Every committed roadmap feature has at least two independent KOL voices
  on file _(basis: evidence-sufficiency stand-in; the KOL program sets no formal
  floor — unvalidated, challengeable)_.
- "Independent voices" is operationalized as distinct kol_id within one simulated
  panel — a weaker notion of independence than the expectation intends; stated.

## Assertions & limits

This answer asserts: per-feature documented voice counts, sentiment mixes, single-voice
features, the E-16.1 verdict, which scheduled wave slots lack documented endorsement
(concern-majority, evidence-absence reading), and — above all — that the entire
evidence base is simulated panel material with zero real collected KOL evidence. It
does **not** assert: what real KOLs think (nobody has been contacted), that the panel
*opposes* any flagged slot (the 3-value vocabulary flattens conditional support into
concern — stated limitation), that sentiment-flagged waves should move (that is
BQ-17's composite and the roadmap council's call), or evidence sufficiency in any
regulatory sense.
