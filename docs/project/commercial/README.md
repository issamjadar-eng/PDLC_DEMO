# Commercial — business-question answers

The **answer tier** of the commercial analytics stack, managed by the `commercial` skill:
`corpus/` (data) → **`commercial/` (answers)** → project console (display). The
business-question catalog lives in `commercial.yml`; each implemented question has a
deterministic computation in `computations.py` that reads **pinned corpus snapshots**
and emits an **answer edition** — a claim-linted `report.md` + `data.json` whose every
figure carries a machine-resolvable marker (`[src: dataset@snapshot]`, `[assume: A-NNN]`,
`[derived: id]`, `[config: path]`).

## Structure

| Item | Purpose |
|------|---------|
| `commercial.yml` | The 30-question catalog (id, question, category, personas, cadence; corpus deps + computation for implemented ones) |
| `computations.py` | Project-owned deterministic computations — the ONLY place numbers are produced |
| `entity-aliases.yml` | Versioned entity-normalization map for public FDA identity fields |
| `plans/BQ-NN.md` | User-owned analysis plans — committed definitions + declared verification-gate checklist, hash-pinned into editions (see its README) |
| `reports/BQ-NN/<edition>/` | Answer editions: report.md, data.json, pins.json, edition.yml (pins plan + code artifacts), approval.yml |
| `code-quality/` | Engine-managed code-quality store (`records.yml`) — deterministic check results + AI code reviews per artifact sha (soft gate; see its README) |
| `.console/commercial-index.json` | Sidecar consumed by the project console (pure consumer) |

## Conventions

- All operations go through the skill: `python3 .claude/skills/commercial/scripts/commercial.py
  {answer|lint|approve|render|check|catalog}`.
- **Never hand-edit editions.** Drafts are regenerated by `answer`; approved editions are
  hash-pinned — `check` treats post-approval mutation as tampering. Fix the computation
  or catalog, then re-answer.
- **Lifecycle**: draft → approved (gated: lint + freshness green, `approve --by <name>`)
  → superseded. Approval of substantive new answers follows an adversarial verification
  pass (independent re-derivation from pins alone), referenced via `--verify-note`.
- Answers over internal (fabricated) datasets carry the `_Demo sample data — not for
  clinical use._` banner, stamped by the computation.
- Unimplemented questions stay visible in the catalog and sidecar as `not-implemented` —
  roadmap, never silence.
