# Finance — business-question answers

The **Finance** business domain: the second domain of the `commercial` skill's answer
engine (one engine, N roots — see the skill's "Domains" section). Same three-tier stack
as commercial: `corpus/` (data) → **`finance/` (answers)** → project console (display).
The finance question catalog lives in `finance.yml`; each implemented question has a
deterministic computation module under `bq_modules/` that reads **pinned corpus
snapshots** (`corpus/finance/*` and, cross-domain, `corpus/commercial/*`) and emits an
**answer edition** — a claim-linted `report.md` + `data.json` whose every figure carries
a machine-resolvable marker (`[src: dataset@snapshot]`, `[assume: A-NNN]`,
`[derived: id]`, `[config: finance.yml]`).

Scope: margin and standard-cost variance, cost of quality and warranty, working capital,
budget vs plan. Every current answer is over **demo-fabricated internal data** and carries
the `_Demo sample data — not for clinical use._` banner.

## Structure

| Item | Purpose |
|------|---------|
| `finance.yml` | The 10-question catalog (FQ-01..FQ-10) with the `domain:` identity block, lint extensions, terms dictionary, categories; corpus deps + computation + params + expectations for implemented ones |
| `computations.py` | Domain-local shared helper layer (pin loading, expectations, narrative/report rendering, dispatch) — no question-specific code |
| `bq_modules/fq_nn.py` | One deterministic computation module per implemented question, exposing `run(corpus_root, out, pins)` |
| `plans/FQ-NN.md` | User-owned analysis plans — committed definitions + declared verification-gate checklist, hash-pinned into editions (see its README) |
| `reports/FQ-NN/<edition>/` | Answer editions: report.md, data.json, pins.json, edition.yml, quality.json; approval.yml once approved |
| `code-quality/` | Engine-managed code-quality store (`records.yml`) — deterministic check results + AI code reviews per artifact sha (soft gate; see its README) |
| `.console/finance-index.json` | Sidecar consumed by the project console (pure consumer; schema 1.5 with the `domain` block) |

## Conventions

- All operations go through the skill with the domain flag:
  `python3 .claude/skills/commercial/scripts/commercial.py --domain finance
  {answer|lint|approve|render|check|catalog|plan-init|code-audit}`.
- **Never hand-edit editions.** Drafts are regenerated by `answer`; approved editions are
  hash-pinned — `check` treats post-approval mutation as tampering. Fix the module or
  catalog, then re-answer.
- **Lifecycle**: draft → approved (gated: lint + freshness green, `approve --by <name>`)
  → superseded. Approval of substantive new answers follows an adversarial verification
  pass (independent re-derivation from pins alone), referenced via `--verify-note`.
- **Cross-domain pins are normal.** Finance questions cite `commercial/internal-financials`,
  `commercial/internal-fleet`, `commercial/internal-complaints` alongside `finance/*`
  datasets; pin freshness follows each dataset's own `max_age_days`.
- **Ratios aggregate by implied daily flow, never by averaging ratios** (DSO = Σ AR ÷
  Σ (AR ÷ DSO); inventory days likewise) — the convention the `internal-ar-inventory`
  README declares.
- Plan constants (targets, tolerances, floors) live in `params` and are cited as
  `[config: finance.yml]`; where a constant is a stand-in with no plan of record behind
  it, the expectation is declared `validated: false` and its basis carries `[VERIFY]`.
- Unimplemented questions stay listed in the catalog (no `computation:` key) and are
  rendered in the sidecar as `not-implemented` — roadmap, never silence.
