# Manufacturing — business-question answers

The **answer tier** for the Manufacturing business domain — a sibling root of
`commercial/` served by the same engine (the `commercial` skill, invoked with
`--domain manufacturing`): `corpus/manufacturing/` (data) → **`manufacturing/`
(answers)** → project console (display, tab `/domains/manufacturing`). The question
catalog lives in `manufacturing.yml`; each implemented question has a deterministic
computation module under `bq_modules/` that reads **pinned corpus snapshots** and emits
an **answer edition** — a claim-linted `report.md` + `data.json` whose every figure
carries a machine-resolvable marker (`[src: dataset@snapshot]`, `[assume: A-NNN]`,
`[derived: id]`, `[config: manufacturing.yml]`).

Scope: first-pass yield and scrap/rework, nonconformance and CAPA posture, supplier
quality, process-validation and calibration currency, and (roadmap) capacity, lot
release, obsolescence, recall scoping, cost of quality, design-transfer readiness.

_Demo sample data — not for clinical use._ Every dataset this domain reads is
demo-fabricated (`corpus/manufacturing/internal-*`); the computations stamp that banner
into each report.

## Structure

| Item | Purpose |
|------|---------|
| `manufacturing.yml` | The 10-question catalog (`domain:` identity block, `lint:` exemptions, `terms:`, `categories:`, questions MQ-01..MQ-10 with personas, cadence, corpus deps, params, expectations, explainers) |
| `computations.py` | Domain-local copy of the shared helper layer (pin loading, as-of anchoring, expectations, narrative, dispatch) — no question-specific code |
| `bq_modules/mq_nn.py` | One deterministic computation per implemented question, exposing `run(corpus_root, out, pins)` |
| `plans/MQ-NN.md` | User-owned analysis plans — committed definitions + declared verification-gate checklist, hash-pinned into editions (see its README) |
| `reports/MQ-NN/<edition>/` | Answer editions: report.md, data.json, pins.json, edition.yml (pins plan + code artifacts), quality.json; approval.yml once approved |
| `code-quality/` | Engine-managed code-quality store (`records.yml`) — deterministic check results + AI code reviews per artifact sha (soft gate; see its README) |
| `.console/manufacturing-index.json` | Sidecar consumed by the project console (pure consumer; schema 1.5 carries the `domain` block) |

## Conventions

- All operations go through the engine from the project root:
  `python3 .claude/skills/commercial/scripts/commercial.py --domain manufacturing
  {answer|lint|approve|render|check|catalog|plan-init|code-audit|audit}`.
- **Never hand-edit editions.** Drafts are regenerated by `answer`; approved editions are
  hash-pinned — `check` treats post-approval mutation as tampering. Fix the module or the
  catalog, then re-answer.
- **No clocks.** Urgency and aging math anchors on the pinned snapshot's provenance
  `as_of` (`computations.snapshot_as_of`), never the machine date, so an edition is
  reproducible.
- **Lifecycle**: draft → approved (gated: lint + freshness green, `approve --by <name>`)
  → superseded. Approval of substantive new answers follows an adversarial verification
  pass (independent re-derivation from pins alone), referenced via `--verify-note`.
- Thresholds (yield floor, reject ceiling, effectiveness floor, due-soon window) are
  `params` in the catalog, cited as `[config: manufacturing.yml]`, and declared as
  `expectations` with `validated: false` until a procedure or plan of record ratifies
  them — every such basis carries `[VERIFY]`.
- Standards / regulation references: the QMSR (21 CFR Part 820) applicability analysis
  under `docs/external/regulations/` is the distilled regulatory source. ISO 13485 is
  deliberately not distilled under `docs/external/standards/` (QMS-level, per that
  folder's README); where a QMS obligation is meant, cite the governing SOP under
  `docs/internal/source-md/quality-management/` (e.g. `GL-SOP-QM-002` Management Review,
  `GL-SOP-QM-004` Internal Audit) rather than an ISO clause number.
- Unimplemented questions stay listed in the catalog (no `computation:` key) and are
  rendered in the sidecar as `not-implemented` — roadmap, never silence.
