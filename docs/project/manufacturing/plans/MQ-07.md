## Question

Recall scoping via lot genealogy — if a component lot or process window is implicated, which finished lots and fleet devices are affected?

**Asked by**: vp-quality, coo · **cadence**: on-demand

## Goal — the decision this answer serves

The field-action scoping decision: given an implicated component lot, station, or
process window, how many finished lots and which installed devices are affected — so a
correction or removal is sized to the affected units, not the whole fleet.

## Approach

Roadmap — **not implemented**. Committed definitions for when it is:

- **Affected lots** = finished lots whose genealogy contains the implicated component
  lot, or whose station pass falls inside the implicated process window (site, station,
  date range, hw rev).
- **Affected devices** = fleet serials built from the affected lots, with site and
  region from the fleet registry.
- **Comparator** = public recalls in the infusion-pump category (openFDA) for the same
  failure class, to size the precedent.

## Data

Registered corpus dependencies:
- `manufacturing/internal-production-lots`
- `commercial/openfda-recalls-infusion`
- `commercial/internal-fleet`

Data we have: lots by line / rev / station / site / date; fleet devices by model / hw
rev / site; public recall records. Data we still need (the gap that keeps this question
`not-implemented`): the **lot-to-serial genealogy** (which device serials came from
which finished lot, and which component lots went into each) — the lot record and the
fleet registry share model and hw rev but no lot / serial key.
