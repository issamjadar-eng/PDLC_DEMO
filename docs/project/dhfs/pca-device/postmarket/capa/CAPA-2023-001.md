# CAPA-2023-001 — PP3500 Decimal-Point Entry Legibility

## Event Description

Beginning in early January 2023, GlobalLogic Post-Market Surveillance received clustered complaints from pharmacy informatics leads at three customer hospitals reporting that nurses were misreading the decimal point on the PP3500 dose-entry confirmation screen. In two cases the misread led to a near-miss 10-fold dose entry (e.g., a programmed `0.5 mL/hr` was read aloud during double-check as `5 mL/hr`); in one case the inverse 0.1x error was reported. All near-miss events were intercepted by the institutional independent double-check before patient harm. No serious adverse events occurred.

Affected configurations:

- Device model: PP3500, all serial numbers
- Affected software versions: 1.2.0, 1.2.1, 1.2.2
- Affected display: 3.5" color LCD (320x240)
- Care settings: hospital med-surg and post-anesthesia care units

Initial complaint reports: COMP-2023-001 through COMP-2023-003 (10–14 January 2023). By 2023-01-20 the count had risen to 12 related complaints.

## Root Cause Analysis

A 5-Why analysis was performed by GlobalLogic Quality Engineering with input from Human Factors and Software:

1. Why did nurses misread the value? — At typical bedside viewing distance (approximately 0.8 m, off-axis), the decimal point glyph rendered as a single pixel and was difficult to distinguish from an artifact or smudge.
2. Why was the glyph that small? — The dose entry field used a numeric font sized for value legibility but the decimal separator was not given a dedicated minimum-pixel-count specification.
3. Why was there no compensating workflow safeguard? — The dose confirmation screen displayed the numeric value as a single string with no explicit prompt highlighting decimal placement.
4. Why didn't the drug library catch the discrepancy? — Drug-library soft and hard limits were applied to absolute values; for low-flow therapies (under 25 mL/hr) the library did not perform a 10-fold deviation check against the prescribed-vs-entered value.
5. Why was this not detected pre-market? — Summative usability validation tested decimal entry under controlled lighting at 0.5 m on-axis; the tested condition under-represented the off-axis bedside double-check workflow that surfaced the issue in the field.

Contributing factors: low decimal-point pixel count, single-string presentation of the entered value, absence of a dose-magnitude sanity check in the drug library, and a usability validation gap.

## Containment

- 2023-01-20: Field Safety Notice **FSN-2023-001** issued to all PP3500 customers, instructing institutions to (a) read decimal placement aloud during the independent double-check using the phrase "point" rather than the implied value, (b) increase display brightness, and (c) use the bedside Quick Reference Card decimal-check addendum.
- 2023-01-25: Customer Service hotline staffed for FSN inquiries.
- 2023-02-15: Software hotfix planning kickoff.

## Corrective Action

A short-term software mitigation and a permanent design fix were defined.

**Short-term mitigation — Software v1.2.4 (released 2023-04-10):**

- Decimal point glyph enlarged 3x and rendered in high-contrast amber.
- Confirmation screen reformatted to show value with the integer and fractional components separated (e.g., `0` `.` `5` `mL/hr`).

**Permanent corrective action — Software v1.3.0 (released 2023-05-15):**

- Dedicated minimum-pixel-count specification added for decimal separator (8 px minimum at 320x240).
- Explicit double-confirmation prompt added on the dose confirmation screen requiring the operator to acknowledge decimal placement.
- Drug-library 10-fold deviation check enabled for all infusions under 25 mL/hr, comparing entered value to a configurable expected-range envelope.
- Display contrast ratio increased.

Design control remediation flowed into a new design input **DI-013** (USAB/CTS — Unambiguous Decimal-Point Entry, summative usability validation under bedside off-axis conditions) and traced back to user need **UN-007** (medication safety / unambiguous dose entry).

## Effectiveness Check

A 90-day field monitoring period was conducted following v1.2.4 deployment (2023-04-10 to 2023-07-10). Complaint trending was extended through year-end 2023.

| Period | Decimal-point misread complaints | Devices in field |
|---|---|---|
| Jan 2023 (pre-FSN) | 12 | ~3,600 |
| Feb–Mar 2023 (FSN active, pre-fix) | 4 | ~3,650 |
| Apr 2023 (v1.2.4 rollout) | 1 | ~3,700 |
| May–Dec 2023 (post-fix) | 0 | ~3,800 |
| Jan 2024 onward | 0 | ~4,100 |

No misread events have been reported since April 2023. Effectiveness confirmed.
