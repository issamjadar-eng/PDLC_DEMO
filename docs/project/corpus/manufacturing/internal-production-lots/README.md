# Corpus dataset — `manufacturing/internal-production-lots`

_Demo sample data — not for clinical use._

**Demo-fabricated** production lot records, 2025-01 through 2026-08 (672 rows: one per
station lot — a batch of units booked through one line station; data through
2026-08-31). Generated by the seeded `gen.py` (seed 42, no clocks) — the stand-in for
an MES / lot-traveler export in a real deployment. Product lines are the five device
lines (IP5000, PP3000, PP3500, SP6000, SP6500) across two fictional plants (Eastbrook:
PP3500/PP3000/IP5000; Westfield: PP3500/SP6000/SP6500) and four stations (SMT,
final-assembly, test, pack). `hw_rev` reuses the `commercial/internal-fleet` letters
(PP3500 A/B, with C the 2026 revision; `-` for lines with no tracked rev).

**Narrative knobs seeded** (honest list — these are modeled, not observed; each is
asserted by `check_knobs.py` on every acquire / validate):

- **PP3500 rev C first-pass yield dips at the test station in 2026-Q2** (rev C test FPY
  ~89% Apr–Jun vs ~96% for rev B at the same station), with partial recovery from July.
  Rev C share of PP3500 lots ramps from 2026-03 (15%) to 90% by 2026-08.
- **Westfield's release lead time trends up** (~9 d mean in 2025 → ~14 d in 2026);
  Eastbrook stays flat (~8 d).
- **8 lots started 2026-06..2026-07 have `dhr_complete=false`** and are therefore
  unreleased (blocked) well past the normal lead time — distinct from late-August lots
  still in process (unreleased, DHR complete).
- Baseline FPY by station ≈ SMT 97%, final-assembly 96.5%, test 96%, pack 99%, ±1.2 pts
  per-lot noise; first-pass failures split into rework vs scrap per station.

**Consumed by**: MQ-01 (first-pass yield, scrap, rework — where and since when), MQ-08
(PP3500 rev C release blockers, joined with `internal-process-validation`); roadmap
MQ-02 (capacity), MQ-04 (release lead time / DHR completeness), MQ-07 (lot genealogy),
MQ-09 (cost of scrap/rework).

## Conventions

- Managed by the `corpus` skill (`corpus.py`). Snapshots under `snapshots/` are immutable —
  never hand-edit; re-acquire instead. `dataset.yml` is the config; `latest` points at the
  newest valid snapshot. Assumptions in `assumptions/A-NNN.yml`, waivers in `waivers/W-NNN.yml`.
- Regenerate via `corpus.py acquire` (iterate with `--dry-run`) — never edit CSVs. The
  generator is deterministic (seed 42, fixed `DATA_THROUGH` horizon, no clocks);
  `data_through: 2026-08-31` lands in provenance as `as_of` for consumers' aging math.
- Booleans are the strings `true` / `false` (pinned by `asserts.enums`).
