# Corpus dataset — `commercial/internal-telemetry-utilization`

_Demo sample data — not for clinical use._

**Demo-fabricated** monthly infusion-utilization telemetry for Cloud Suite CONNECTED
devices only: 331 devices x 6 months (2026-02..2026-07) = 1,986 rows, with a
per-segment expected-hours norm (academic 480, idn 450, community 400, home-infusion
280 hrs/device/month; segment derived from a stable hash of `site_id`, identical
across the internal generators). Generated by the seeded `gen.py` (seed 42) — the
stand-in for the Cloud Suite telemetry warehouse export. The device set equals the
shared fleet model's connected devices exactly (identical embedded fleet model, same
seed), so joins against `internal-fleet` and `internal-subscriptions` reconcile.

**Consumed by**: BQ-11 (adoption divergence — the sold-but-underused early warning).

## Narrative knobs (seeded, measured on snapshot 2026-07-27)

- **6 underused sites (<50% of expected hours)** — S-NA-03 (37.1%), S-NA-13 (34.9%),
  S-NA-16 (35.3%), S-NA-22 (35.6%), S-EMEA-02 (36.9%), S-APAC-06 (37.0%). Their
  device-months are drawn at 25-48% of the segment norm; picked from sites with ≥5
  connected devices so the signal is not one-pump noise.
- **Everything else 70-110%** — non-underused site-level utilization spans 85.7-97.0%.

No clocks in the generator — months are literal; current-state through 2026-07.

## Conventions

- Managed by the `corpus` skill (`corpus.py`). Snapshots under `snapshots/` are immutable —
  never hand-edit; re-acquire instead. `dataset.yml` is the config; `latest` points at the
  newest valid snapshot. Assumptions in `assumptions/A-NNN.yml`, waivers in `waivers/W-NNN.yml`.
- Regenerate via `corpus.py acquire` — never edit CSVs.
