# Corpus dataset — `commercial/internal-winloss`

_Demo sample data — not for clinical use._

**Demo-fabricated** CRM opportunity win/loss log: 120 opportunities closing
2025-01-03..2026-07-20 across installed-base sites (shared fleet `S-{REGION}-NN` ids)
and prospects (`PRO-NN`, each with one stable region/segment identity drawn from a
dedicated rng stream keyed by the prospect id). Generated by the seeded `gen.py` (seed 42) — the stand-in for
a CRM opportunity export in a real deployment. Account names are fictional; competitor
and incumbent vendor names are real (BD, Baxter, ICU Medical, Fresenius Kabi, Smiths
Medical, B.Braun) inside fabricated records — the demo banner marks every row as
fabricated. Site ids/segments align with the other `internal-*` datasets (identical
embedded fleet model + segment hash, same seed).

**Consumed by**: BQ-08 (win/loss drivers), BQ-09 (competitor-disruption conversion —
the elevated-win cluster is joined downstream against REAL openFDA recall dates from
`commercial/openfda-recalls-infusion`).

## Narrative knobs (seeded, measured on snapshot 2026-07-27.4)

- **Overall win rate ≈45%** — actual 45.8% (55/120).
- **Predictive-monitoring gap in losses ≈30%** — `primary_reason ==
  predictive-monitoring-gap` OR `cites_predictive_monitoring == yes` in 31.0% of the
  42 losses.
- **Disruption-window conversion** — opportunities with `incumbent_vendor` Baxter or
  ICU Medical closing 2025-07-01 onward win at 65.6% (21/32) vs 38.6% (34/88) for
  everything else — **denominators are all outcomes including no-decision**. On the
  decided-only basis (won + lost) used by the BQ answers, the same knob is 77.8%
  (21/27) vs 48.6% (34/70). Close months for that group are clustered in stand-in
  disruption windows:
  Baxter 2025-09..2026-02, ICU Medical 2025-11..2026-04 (wins peak 2025-11..2026-03,
  maximum in 2026-01). These windows are FABRICATED stand-ins for recall/integration
  disruption; the real recall dates live in the openFDA datasets and the join happens
  downstream.

## Conventions

- Managed by the `corpus` skill (`corpus.py`). Snapshots under `snapshots/` are immutable —
  never hand-edit; re-acquire instead. `dataset.yml` is the config; `latest` points at the
  newest valid snapshot. Assumptions in `assumptions/A-NNN.yml`, waivers in `waivers/W-NNN.yml`.
- Regenerate via `corpus.py acquire` — never edit CSVs.
