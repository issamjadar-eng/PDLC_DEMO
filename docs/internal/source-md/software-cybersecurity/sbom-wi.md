# GL-WI-SW-002 — Software Bill of Materials (SBOM) Generation

_Demo sample data — not for clinical use._

**Document ID:** GL-WI-SW-002
**Revision:** 1.0
**Parent SOP:** GL-SOP-SW-004

---

## 1. Purpose

Produce and maintain SBOMs for each GlobalLogic medical device software release, meeting FDA 2023 Cybersecurity Guidance expectations and NTIA SBOM minimum elements.

## 2. Minimum Content (NTIA)

Every SBOM entry includes:

1. Supplier name
2. Component name
3. Version
4. Other unique identifiers (purl, CPE, hash)
5. Dependency relationship
6. Author of the SBOM data
7. Timestamp

## 3. Format

Use **CycloneDX 1.5** or **SPDX 2.3**. Machine-readable; a human-readable summary may be included. Format choice is documented in the Cybersecurity Plan (GL-TMP-SW-002).

## 4. Generation

- Generated by CI at every release build from the lockfile/manifest and container layers
- Includes transitive dependencies
- Includes OS-level components for firmware/OS images
- Stored alongside the build artifact; reproducible from source + build manifests

## 5. Review Before Release

- Match against SOUP inventory (GL-SOP-SW-002) — all SOUP must appear
- No unexpected additions (supply-chain integrity check)
- CVE scan result attached; open CVEs triaged per GL-SOP-SW-004 §6.7

## 6. Distribution

- Provided in premarket submissions per FDA 2023 guidance
- Provided to customers on request (commercial terms permitting)

## 7. Update Cadence

- Regenerated at each software release
- Delta-regenerated on material dependency change; full regen at release candidate
