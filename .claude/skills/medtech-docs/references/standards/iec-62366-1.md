# IEC 62366-1 — Usability Engineering for Medical Devices

**Standard**: IEC 62366-1:2015 + Amd 1:2020
**Category**: Usability
**Recognized by FDA**: Yes — referenced in SW Functions guidance

## Overview

IEC 62366-1 specifies the process for manufacturers to analyze, specify, develop, and evaluate the usability of medical devices as it relates to safety. The standard focuses on preventing **use errors** — situations where the user's interaction with the device leads to a hazardous situation, not because of device failure but because of the user interface design.

## Key Process Requirements by Clause

### Clause 4 — General Requirements

#### 4.1 Usability Engineering Process
- Establish and maintain a usability engineering process
- The process must be integrated with the overall design and development process
- Usability engineering activities must be traceable to the risk management process (ISO 14971)

#### 4.2 Competence
- Personnel performing usability engineering must be competent
- Include expertise in human factors, ergonomics, and the clinical use context

### Clause 5 — Usability Engineering Process

#### 5.1 Use Specification

**5.1.1 Intended Users**
- Identify and characterize intended users
- Consider: clinical role, training level, experience, physical capabilities

**5.1.2 Intended Use Environment**
- Document the use environment for each use scenario
- Consider: lighting, noise, sterility, time pressure, distractions, PPE

**5.1.3 User Interface**
- Identify the user interface components the user interacts with
- For software: screens, controls, navigation, data entry, alerts, visual/audio feedback

#### 5.2 Use-Related Risk Analysis

- Identify hazards and hazardous situations related to use
- Identify potential use errors and their causes
- Evaluate the severity and probability of harm from use errors
- Feed use-related risks into the ISO 14971 risk management process
- Common use error categories for SaMD:
  - Perception errors (information not seen, misread, misunderstood)
  - Cognitive errors (information misinterpreted, wrong decision)
  - Action errors (wrong control activated, wrong sequence, omission)

#### 5.3 User Interface Specification

- Establish the user interface specification from use specification and risk analysis
- Specify: information presentation, controls, navigation, feedback, error prevention
- Include measurable acceptance criteria for critical use scenarios
- **Deliverable**: User Interface Specification

#### 5.4 User Interface Design and Implementation

- Design and implement the user interface per the specification
- Apply human factors principles to minimize use errors

#### 5.5 Verification of User Interface

- Verify the user interface meets the user interface specification
- Include inspection, analysis, and testing methods
- Verify risk control measures related to usability are implemented

#### 5.6 User Interface Evaluation

- Evaluate the user interface with representative users in representative environments
- **Formative evaluation**: Iterative evaluation during design to identify usability problems
  - Methods: cognitive walkthrough, heuristic evaluation, usability testing with think-aloud
  - Can be done with simulated environments and prototype interfaces
  - Multiple rounds expected
- **Summative evaluation**: Final evaluation to provide objective evidence of usability
  - Methods: usability testing with representative users performing critical tasks
  - Must use production-equivalent device in representative use environment
  - Must include statistical evidence that critical tasks can be completed safely
  - **Deliverable**: Summative Usability Evaluation Report

#### 5.7 User Interface of Unknown Provenance (UOUP)

- If reusing an existing user interface or UI components, evaluate them using this process
- Applicable when using third-party UI frameworks or pre-built components in the clinical interface

## FDA-Specific Notes

- FDA expects a Human Factors Validation (summative) report in the 510(k) for Class II SaMD
- Critical tasks must be identified and tested — tasks where use error could cause harm
- FDA may request formative evaluation data in addition to summative
