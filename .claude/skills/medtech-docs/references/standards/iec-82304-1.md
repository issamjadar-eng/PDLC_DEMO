## Overview

IEC 82304-1 addresses the safety of health software products — standalone software (not embedded in a medical device). It covers the entire lifecycle: design, development, validation, installation, maintenance, and disposal. It complements IEC 62304 by focusing on the **product level** rather than the **development process level**.

## Relationship to IEC 62304

| Aspect | IEC 62304 | IEC 82304-1 |
|--------|-----------|-------------|
| Focus | Software development process | Software product safety |
| Scope | Development lifecycle activities | Full product lifecycle (including deployment, maintenance, disposal) |
| Applies to | Software within medical devices AND standalone | Standalone health software products |
| Risk management | Clause 7 (software-specific) | References ISO 14971 at product level |
| Overlap | Development activities | IEC 82304-1 requires conformance to IEC 62304 for development |

## Key Requirements by Clause

### Clause 4 — General Requirements

#### 4.1 Quality Management System
- Health software must be developed under a quality management system
- References ISO 13485 or equivalent

#### 4.2 Risk Management
- Apply risk management per ISO 14971 to the health software product
- Risk management must cover the full product lifecycle
- Include risks from: intended use environment, interoperability, data migration, IT security

#### 4.3 Software Development
- Software development must conform to IEC 62304
- This is where the two standards connect — IEC 82304-1 requires IEC 62304 compliance

### Clause 5 — Health Software Product Requirements

#### 5.1 Intended Use and Operating Environment
- Define the intended use of the health software product
- Define the intended operating environment (hardware, OS, network, interfacing systems)
- Define the intended user profile

#### 5.2 Health Software Product Safety Requirements
- Derive safety requirements from risk management activities
- Include requirements for: data integrity, access control, confidentiality, audit trails
- Address requirements for IT-network integration
- Consider degraded performance modes

#### 5.3 Usability Requirements
- Apply usability engineering per IEC 62366-1
- Document user interface requirements
- Consider use error risks

### Clause 6 — Health Software Product Planning

#### 6.1 Health Software Product Life Cycle Plan
- Plan must cover the entire product lifecycle
- Include provisions for: product deployment, operation, maintenance, and decommissioning
- **Deliverable**: Product Life Cycle Plan

#### 6.2 Maintenance Planning
- Plan for maintaining the health software product after release
- Include: problem tracking, change management, version management

### Clause 7 — Health Software Product Design and Development

#### 7.1 Design and Development per IEC 62304
- Follow IEC 62304 for all software development activities
- No additional development requirements beyond IEC 62304 compliance

#### 7.2 System and Acceptance Testing
- Conduct system testing and acceptance testing at the product level
- Verify that the product meets the defined safety requirements
- Validate in an environment representative of the intended operating environment

### Clause 8 — Health Software Product Verification and Validation

#### 8.1 Verification
- Verify the health software product meets its specified requirements
- Include verification of integration with the intended operating environment

#### 8.2 Validation
- Validate the health software product in the intended operating environment
- Validation must demonstrate the product meets user needs and intended uses
- **Deliverable**: Validation Report

### Clause 9 — Health Software Product Release

#### 9.1 Release Activities
- Ensure all planned activities are complete
- Document known residual anomalies and their risk evaluation
- Provide accompanying documentation (user manual, release notes, installation instructions)
- **Deliverable**: Release documentation

#### 9.2 Accompanying Documents
- User documentation must include: intended use, operating environment requirements, installation instructions, user instructions, known limitations, security guidance
- **Deliverable**: User documentation / labeling

### Clause 10 — Health Software Product Maintenance

#### 10.1 Maintenance Process
- Establish and follow a maintenance process
- Evaluate the impact of changes before implementation
- Apply IEC 62304 software development process to modifications

#### 10.2 Problem Resolution
- Track and resolve problems per a defined process
- Evaluate problem severity and safety impact

### Clause 11 — Health Software Product Decommissioning

- Plan for orderly decommissioning of the software product
- Address data migration, archival, and patient safety during transition
- Notify users of decommissioning timeline and alternatives
