```yaml
  result if the SOFTWARE SYSTEM should fail to behave as specified."
extracted_requirements:

  - "Document the classification rationale referencing ISO 14971 severity levels"
```

```yaml
  "The MANUFACTURER shall define and document the SOFTWARE REQUIREMENTS from the
  SYSTEM REQUIREMENTS and the results of RISK MANAGEMENT activities."
extracted_requirements:
  - "Define software requirements traceable to system-level requirements"
  - "Define software requirements traceable to risk management outputs (risk controls implemented in software)"
  - "Document requirements in a Software Requirements Specification (SRS)"
```

**Context:** The SRS must be bidirectionally traceable — up to system requirements (and ultimately user needs) and down to design outputs (architecture, detailed design). Risk control measures implemented in software must appear as software requirements, not just in the risk file.

## §7 — Software Risk Management Process

<a id="OBL-62304-016"></a>

```yaml
id: OBL-62304-016
title: "Software Hazard Analysis"
source: "IEC 62304:2006+AMD1:2015 §7.1.1"
section: "§7 — Software risk management"
scope_flags: []
topic: risk-management
artifact_type: record
dhf_owner: item
min_iec62304_class: B
applies_to:
  - "Risk Management File"
  - "Software FMEA"
  - "Hazard Analysis"
verbatim: |
  "The MANUFACTURER shall identify SOFTWARE ITEMS that could contribute to a
  HAZARDOUS SITUATION. For each such SOFTWARE ITEM, the MANUFACTURER shall
  evaluate the contribution of the SOFTWARE ITEM to the HAZARDOUS SITUATION."
extracted_requirements:
  - "For each hazardous situation in the risk file, identify which software items could contribute to it"
  - "Evaluate how and to what degree each software item contributes (causal analysis)"
  - "Document results in a software risk analysis record — typically a software FMEA or hazard analysis table"
```

**Context:** This is distinct from ISO 14971's hazard identification — §7.1 requires zooming into the software to trace which specific items (modules, components, algorithms) are involved in each hazardous situation. For AI-enabled items, this means the AI model itself must appear in the software FMEA.
