# Docflow Skill — Design & Architecture

This document describes the design decisions behind the docflow skill. It is not loaded by Claude during normal skill operation — it exists for human understanding.

For skill usage and instructions, see `SKILL.md`.

## Overview

The docflow skill manages document conversion and round-trip workflows between markdown (working format) and formal formats (DOCX, PDF, XLSX). It handles image fidelity, metadata tracking via frontmatter, cross-reference resolution, and batch processing.

## Role in the Ecosystem

docflow sits between the working documents (markdown in docs/) and formal deliverables (DOCX/XLSX in formal/ folders):

```
docs/project/dhfs/<dhf>/design-controls/architecture/
  sad.md                    ← Working document (markdown)
  formal/
    sad.docx                ← Formal deliverable (generated by docflow)
```

## Dependencies

| File | Required by | Purpose | How to create |
|------|-------------|---------|---------------|
| `docs/internal/source/` | `convert` | Source documents (PDF, DOCX) to convert | Place files manually |
| `docs/internal/source-md/` | `convert` | Output location for markdown conversions | `/medtech-docs init` or `mkdir` |
| `pandoc` | Format conversion | Markdown ↔ DOCX conversion | `brew install pandoc` |
| `soffice` (LibreOffice) | PDF/DOCX processing | Headless document conversion | `brew install --cask libreoffice` |
| `pdftotext`, `pdfimages` | PDF conversion | Text and image extraction from PDFs | `brew install poppler` |

When a dependency is missing, the skill reports what's needed and how to install it.

## Key Design Decisions

### Four Document Workflows

| Workflow | Direction | Use case |
|----------|-----------|----------|
| `convert` | Source → Markdown | Convert QMS source docs (PDF/DOCX) to working markdown |
| `export` | Markdown → Formal | Generate DOCX/XLSX from markdown for FDA submission |
| `import` | Formal → Markdown | Pull changes from reviewed DOCX back into markdown |
| `reconcile` | Round-trip | Merge external review edits with local markdown changes |

### Extract-First Image Strategy

When converting source documents, images are extracted first (before text conversion) to preserve fidelity. Images are named using a deterministic convention tied to the document ID and page/figure number.

### Frontmatter Metadata

Every converted markdown file includes YAML frontmatter tracking:
- Source file path and hash (for change detection)
- Conversion date and tool
- Document ID for cross-referencing
- Image manifest

### Batch Processing

The `batch` action processes entire categories of source documents with quality gates between stages. This supports the 127 QMS documents that need conversion.
