# Trace Matrix Skill

Build the bidirectional design-controls trace matrix for any DHF in a medtech-docs project. Usage: `/trace-matrix <action>`

This skill is the **writer**. It parses the design-controls source docs of each DHF, computes the trace graph (UN ↔ DI ↔ Architecture ↔ V&V, with Risk as an overlay), detects orphans and broken references, and emits two artifacts atomically per DHF:

- `design-controls/trace-matrix/trace-matrix.md` — the controlled DHF deliverable (human-readable, full bidirectional)
- `design-controls/trace-matrix/trace-matrix.json` — a structured sidecar consumed by `project-console`'s Trace Matrix section

The sidecar is the contract. The skill knows nothing about the console; the console knows nothing about this skill. They cooperate via the JSON shape and the file-system convention.

## Adapter model (v2, adapter generation)

Different projects author their source docs differently — column headers, ID formats, table shapes, and even file layouts vary. Rather than forcing every project to conform to one hardcoded parser, this skill uses a two-level adapter model:

| Tier | Location | Written by | When used |
|---|---|---|---|
| **Default adapters** | `${CLAUDE_SKILL_DIR}/scripts/parsers/defaults/<layer>.py` | Shipped with the skill | When no project override exists |
| **Project adapters** | `${CLAUDE_PROJECT_DIR}/tools/project-console/trace-matrix/adapters/<layer>.py` | Generated by `/trace-matrix init` or edited by hand | Whenever the file is present |

Both expose the same tiny interface:

```python
def parse(path: Path, layer_cfg: dict) -> ParserResult
```

The loader (`adapter_api.load_adapter`) checks project first, falls back to default. The **build is always deterministic** — adapters are imported by file presence, never generated at build time. LLM/analysis work happens only during `init`, which produces files on disk that subsequent builds import directly.

## Source Files

| File | Purpose |
|------|---------|
| `trace-matrix.yml` (project root) | Per-DHF source map: which file holds each layer, what ID prefix to look for, optional column overrides. Generated by `init`. |
| `${CLAUDE_SKILL_DIR}/scripts/build.py` | Deterministic build CLI. `python build.py [--check] [--dhf <name>] [--repo <path>]` |
| `${CLAUDE_SKILL_DIR}/scripts/analyze.py` | Rational-check CLI used by `init`. Reports per-layer verdicts without writing anything. |
| `${CLAUDE_SKILL_DIR}/scripts/adapter_api.py` | `ParserResult` contract, `rational_check`, `load_adapter` resolver. |
| `${CLAUDE_SKILL_DIR}/scripts/graph.py` | Layer graph + gap engine (orphans, broken refs, reverse edges). |
| `${CLAUDE_SKILL_DIR}/scripts/emit.py` | Atomic markdown + JSON sidecar writers. |
| `${CLAUDE_SKILL_DIR}/scripts/parsers/defaults/*.py` | Shipped defaults for the five layers. |
| `${CLAUDE_SKILL_DIR}/scripts/parsers/markdown_table.py` | Shared GFM pipe-table tokenizer used by every default adapter. |

## Default layer source convention

| Layer | Default source within a DHF | Default ID prefix | Notes |
|---|---|---|---|
| User Needs | `design-controls/user-needs/user-needs.md` | `UN` | Top of trace |
| Design Inputs | `design-controls/requirements/design-inputs.md` | `DI` | Carries both UN upstream edges and V&V downstream edges (from the Verification Method column) |
| Architecture | `design-controls/architecture/<dhf>-system-sad.md` | `M` | v1: nodes-only — Module ↔ DI mapping table is not required to exist; layer renders with `edges_known=false` if absent |
| V&V | `null` (derived from DI verification column) | `VER` | When a real `verification-protocols.md` exists, set `source:` in `trace-matrix.yml` — the adapter override can read it directly |
| Risk | `risk-management/<source>` | `HZ` | If source is empty or an `awaiting-content` placeholder, layer renders with `source_empty` |

All defaults are overridable per DHF in `trace-matrix.yml`. For structural divergences a project adapter file in `tools/project-console/trace-matrix/adapters/` takes over entirely.

## JSON Sidecar Contract (v1.1)

```json
{
  "version": "1.1",
  "dhf": "<DHF name>",
  "generated_at": "2026-04-15T...",
  "layers": [
    {
      "key": "user_needs",
      "title": "User Needs",
      "id_prefix": "UN",
      "source_files": ["docs/project/dhfs/<dhf>/design-controls/user-needs/user-needs.md"],
      "items": [
        {
          "id": "UN-001",
          "summary": "...",
          "full_text": "...",
          "category": "CLIN",
          "criticality": null,
          "group": "G1",
          "stakeholder": "...",
          "priority": "High",
          "source_ref": "...",
          "traces_forward": [
            {"id": "DI-001", "summary": "..."}
          ],
          "traces_reverse": []
        }
      ],
      "missing_reason": null,
      "edges_known": true,
      "warnings": []
    }
  ],
  "edges": [{"from": "UN-001", "to": "DI-001"}],
  "gaps": {
    "orphans": {"user_needs": [], "design_inputs": [], "vnv": [], "architecture": [], "risk": []},
    "broken_refs": [],
    "empty_layers": []
  },
  "stats": { ... }
}
```

The sidecar is **self-contained** — labels and full text are inlined per item so the console can render expandable rows without a second fetch. `source_files` lets the console build "↗ View in source" links without hardcoding any paths.

## Actions

Parse the user's argument string `$ARGUMENTS` to determine which action to perform.

### `init`

First-time setup. Idempotent — safe to re-run.

**Steps**:
1. Read `project.yml` and enumerate `dhfs[]`.
2. If `trace-matrix.yml` does not exist, write a default one mapping each DHF's layers to the conventional source paths.
3. For each DHF × layer, run `python ${CLAUDE_SKILL_DIR}/scripts/analyze.py --dhf <name> --json` to get per-layer rational-check verdicts.
4. For each layer whose verdict is `ok: false` **with a non-empty source** (a parser problem, not a data gap):
   - Read the source document directly.
   - Generate a Python adapter file tailored to that document's observed shape (column headers, ID format, trace column semantics, etc.). The adapter must expose `def parse(path, layer_cfg) -> ParserResult`.
   - Write it to `tools/project-console/trace-matrix/adapters/<layer>.py`.
   - Append a rationale block to `tools/project-console/trace-matrix/analysis-notes.md`: what the defaults returned, what the source actually looks like, what the generated adapter does differently.
5. Run `python ${CLAUDE_SKILL_DIR}/scripts/build.py --repo ${CLAUDE_PROJECT_DIR}` and confirm no regressions.
6. Print a summary: which layers used defaults, which got generated adapters, which still have data gaps that no adapter can fix.

**Flags**:
- `--regenerate` — force re-generation of existing adapters. Without this, init never overwrites a project adapter file.
- `--dhf <name>` — restrict to one DHF.
- `--layer <key>` — restrict to one layer (requires `--dhf`).

### `build [--dhf <name>] [--check]`

Parses sources via the resolved adapters, computes the graph, writes outputs. **Deterministic — no LLM.**

**Steps**:
1. Read `trace-matrix.yml`.
2. For each DHF (or just `--dhf <name>`):
   - Resolve the adapter for each layer via `load_adapter`.
   - Run parsers against the configured sources.
   - Build the graph; compute orphans, broken refs, reverse edges.
   - Emit `trace-matrix.md` and `trace-matrix.json` atomically.
3. With `--check`: do everything except write. Exit 1 if any gap is found.
4. Print a per-DHF summary table to stdout showing layer counts, orphans, and whether each layer used `[deflt]` or `[proj]` adapter.

### `check`

Alias for `build --check`. Hook/CI friendly.

### `analyze`

Run the rational check against the currently resolved adapters and print a verdict, without any other side effects. Useful for debugging "why did my source doc not parse?"

## Best Practices

| # | Practice | Why |
|---|---|---|
| 1 | **Skill is the only writer.** Console (or any other reader) must never compute traces — only read the JSON sidecar. | Single source of truth for trace logic. Bugs fixed in one place. |
| 2 | **Show missing as missing.** Never paper over empty layers, broken refs, or absent trace data. Render them as visible gaps. | The trace matrix is most valuable as a scoreboard for what's not done yet. |
| 3 | **Build is deterministic.** LLM work only at `init`. Build imports files, runs Python, writes outputs. | Predictable, debuggable, and cheap to run in hooks or CI. |
| 4 | **Project adapters beat shipped defaults.** Presence of `tools/project-console/trace-matrix/adapters/<layer>.py` is the override signal. No registry, no flags. | Minimum ceremony. The file system is the registry. |
| 5 | **The JSON shape is the contract.** Bumping `version` requires a coordinated release with project-console. | Loose coupling depends on shape stability. Minor additive fields are backwards-compatible (1.0 → 1.1 ok). |
| 6 | **Atomic emits.** Write to `.tmp` and rename. Never leave a partially written `trace-matrix.json`. | The console may be reading at the same moment a build runs. |
| 7 | **Inline labels in the sidecar.** Each item carries its own summary; each trace edge carries the target's summary too. | Console renders expandable rows with no second fetch. |
| 8 | **Per-DHF independence.** A failure parsing one DHF must not block others. | Demo projects often have uneven DHFs. |
| 9 | **Rational check before adapter generation.** Defaults are the fast path. Only generate an adapter when defaults *and* project data are both present and the defaults fail to extract what's clearly there. | Avoid generating adapters that mask a missing-data gap as a parser gap. |
