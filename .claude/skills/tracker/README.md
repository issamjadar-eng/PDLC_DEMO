# tracker — Design & Architecture

This document is not loaded by Claude during normal skill operation — it exists for human understanding.

For skill usage and instructions, see `SKILL.md`.

## Best Practices

| Check | How to Verify | Severity | Scope |
|-------|--------------|----------|-------|
| Tracker markdown exists | `docs/project/submissions/submission-tracker.md` exists | Required | shared |
| Tracker HTML exists | `docs/project/submissions/submission-tracker.html` exists | Required | shared |
| Render script exists | `.claude/skills/tracker/scripts/render.py` exists | Required | shared |
| Composition manifest parses | `composition-manifest.md` exists in this filing folder and has the required sections (Filing Identification, Included Pieces, Excluded Pieces, Cross-references, Reviewer Sign-off) | Required | per-submission |
| Composition manifest pieces resolve | Every "Included piece" referenced in this filing's composition manifest resolves to an existing file under `docs/project/dhfs/<dhf>/...` | Required | per-submission |

## Changelog

- 13 (2026-06-02): **`frontend-design` dashboard refresh — brand-alignment + depth/motion (R1+R2).** Brought the rendered submission-tracker dashboard into visual alignment with the project-console it embeds inside. The dashboard renders in an isolated context (iframe / embed route), so it never inherited the console's `console.css` refresh (ben/073) — its look is wholly owned by `render.py`'s embedded CSS. **R1 — brand + font alignment:** new `load_brand_theme()` resolves the active console theme (`tools/project-console/console.yaml` `theme:` → theme pack `theme.yaml`, following `extends:`, regex-parsed to avoid a YAML dep) and injects `--brand` (theme `primary`) + `--font` (theme `font_body`) into the dashboard `:root` via `gen_theme_css()`, in both the standalone-file and embed render paths. **Falls back silently** to the self-contained slate+sky defaults baked into `_CSS_BASE_INNER` when no project-console/theme is found — the skill stays standalone and project-agnostic (no hard dependency). The new `--brand` token repaints chrome/hero accents only (header title, active filter pills, scale-section headings, action-button hover); the data-carrying `--accent`/status/scope/phase/effort colors are intentionally left on the sky/multi palette so badge distinction is preserved (avoids collision with the help-row purple + `--eng`). **R2 — depth + motion + type:** layered `--shadow-sm`/`--shadow-md` scale applied to summary cards, categories, and the scale section; one `prefers-reduced-motion`-guarded page-load stagger (`pc-rise`) on the summary cards (initial `opacity:0` lives only inside the `no-preference` query, `backwards` fill, so reduced-motion users always see full content); tighter header tracking. **Files:** `scripts/render.py` (`_read_theme_yaml` / `load_brand_theme` / `gen_theme_css`; `:root` tokens; hero→`--brand` repointing; card shadows; motion block; theme injection in both render paths). Verified in Chrome via the console `/dashboards/submission-tracker` view: active pills render GlobalLogic purple, cards elevated + animated, zero console errors, filters/expansion intact. Task ben/076.

- 12 (2026-05-06): **Dashboard polish — color-coded legend labels + readable disabled action buttons.** Two visual fixes to `render.py` after dark-theme adoption surfaced low-contrast spots: (1) the per-status legend strip ("Approved / In Review / Drafted / Drafting / Needs Revision / Not Started") now color-codes each label to match its dot, so at-a-glance scanning maps text↔bar without re-reading the dot. New `.legend-item.l-{done,in-review,drafted,partial,needs-revision,not-started}` modifier classes; matching class added to each rendered legend item in the assemble path. (2) Disabled `.tracker-action-btn` (e.g. "Create Draft" placeholders) was rendering as opacity-0.5 over the same surface color as its background — text was effectively invisible. Now: transparent bg, dashed border, slate-400 text at 0.85 opacity → clearly readable but visually distinct from active buttons. Active state simultaneously upgraded to `--surface2` bg + `--text` color (was `--text-muted`) so the click target reads as actionable. **Files:** `scripts/render.py` (legend CSS + classes; `.tracker-action-btn` rule trio).

- 11 (2026-05-04): **Safety default: bare `--md` auto-targets the candidate file.** Previously `python3 generate.py --md` printed the candidate to stdout — useful for piping but easy to confuse with "ready to overwrite the canonical." Now the safe path is the default: `--md` without `--out`/`--candidate`/`--write-canonical` auto-writes to `submission-tracker.candidate.md` with a stderr note explaining how to opt into the canonical write path. Canonical overwrite still requires the explicit `--write-canonical` flag plus an `--out <canonical_path>`. Motivated by a near-miss in task ben/165: a test cutover diff showed `emit_full_markdown()` produces a substantial subset of the canonical (drops ~13 structural sections including legends, Reviewer Sign-off, Changelog, plus all 11 hand-authored Deliverable Details blocks). Cutover-readiness gap captured in task; safety default lands now to make further cutover testing risk-free.
- 10 (2026-05-04): **Model D — user-injected row registry.** Added six actions (`add-row`, `update-row`, `remove-row`, `list-user-rows`, `validate-rows`, `import-user-rows`) with new agent (`agents/user-row-author.md`), schema (`schemas/user-row.schema.yml`), and validator (`scripts/validate-user-rows.py`). Rows that don't derive from the milestone catalog × composition manifests × DHF evidence pipeline now live in `docs/project/submissions/tracker-user-rows.yml` (machine-managed via the new actions). `generate.py` extended with `read_user_rows()` + `emit_row_source_sidecar()` so user rows merge into the row inventory and the per-row `submission-tracker.row-source.json` sidecar tags each row's `source_kind` (user | derived). `render.py` extended with `load_row_source_sidecar()` + `source_badge_html()` to add a small ★ badge on user-injected rows in the dashboard chrome (hover-tooltip surfaces the row's `reason`). Validator is project-adaptive: vocabularies for scope/phase/effort/status are resolved at runtime from `project.yml` + `regulatory.yml`. Honors `TRACKER_SKIP_USER_ROWS=1` env var to break the chicken-and-egg between validator collision-check and the merged generator inventory. Schema enforces `id` regex (no collision with generator IDs), required fields (id/name/scope/phase/status/reason), and an auto-managed `_meta` block (`created_by`, `created_at`, `last_updated_at`). Boundary clarified in SKILL.md: registry is storage, the skill is the API, the `user-row-author` agent is the schema-aware authoring assistant.
- 9 (2026-05-04): Added `enrich-details` action — deterministic sibling of `enrich-help`. New agent (`agents/details-author.md`), bundle builder (`scripts/build-detail-context.py`), and sidecar (`docs/project/submissions/submission-tracker.details.json`) populate per-row Phase / Scope / Path / Primary REF / All applicable REFs / Notes blocks. Sidecar entries support multi-row attachment via `row_ids: [...]` so one entry can cover sibling rows that share an artifact (e.g. an early-phase readiness row + the final-package row pointing at the same SAD). `render.py` extended with `load_details_sidecar()` + `_details_entry_to_md()`; when the sidecar is present, it overrides the inline `## Deliverable Details` markdown section. Legacy inline path is unchanged when no sidecar exists. Boundary clarified in SKILL.md: `enrich-help` = LLM artifact explainer (`(?)` panel); `enrich-details` = deterministic projection (`(i)` panel).
