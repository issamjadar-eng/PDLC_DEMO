# Document-type authoring notes

The W/R/D rules in `authoring-standard.md` apply to **every** controlled document. This file adds the **per-doctype** layer: each regulated doctype has a characteristic *register* (how formal, how declarative), a characteristic *form* (the shape the reader expects), the handful of rules that **bite hardest** for it, and — because writing-quality tools are tuned for general prose — a distinct profile of **which "AI-slop"/quality signals transfer vs. which are false positives** for that doctype.

**How to use:** before authoring or copy-editing a controlled document, (1) read its row + note below, (2) read the universal rules it leans on, (3) apply the `writing-well` `slop`/`lint_prose` passes only through the register filter in the last column. Load on demand; not part of the default rule index.

## Quick map

| Doctype | Register | Characteristic form | Rules that bite hardest | Slop/quality signal to ACT on · to IGNORE (register false-positive) |
|---|---|---|---|---|
| **Cover letter** (Q-Sub / 510(k)) | Formal request | FDA Appendix-1 letter: purpose → device summary → pathway → the questions → logistics; Attachments list aligns 1:1 with the composition manifest | R1 (no promissory "we will"), R1.3 (recite obligations, don't perform them), W11 (no marketing) | **Act:** em-dash density (prose-heavy, most visible here). **Ignore:** — |
| **Device description** | Declarative, as-delivered | What the device *is* + module architecture at system altitude; clinical setting; SaMD/non-SaMD boundary | R1 (present tense), D12 (modality-specific / instance-generic), W12.1 (reference the fact, restate the gist), no device-status meta-argument | **Act:** em-dash density. **Ignore:** `**Bold:**` module/attribute lists |
| **Intended Use / IFU** | Legal string | The canonical who/what/input/purpose/setting statement, **reused byte-verbatim** everywhere it appears | **D13** (canonical form, verbatim reuse; "clinical" never on an admin function), R1, near-zero tolerance for any flourish | **Act:** any em-dash, hedge, or booster — an IFU is a legal string, keep it plain and minimal. **Ignore:** — |
| **Specific Questions for FDA** | Interrogative | Per-question block: *Question → Context → Preliminary position → refinement follow-up*; stable Question Keys; ≤ the guidance topic ceiling | R2-adjacent (each question testable/answerable), D14.4 (confirmation token is the one sanctioned hedge), W5 (topic-sentence-first per question) | **Act:** em-dash density. **Ignore:** per-question `**Bold:**` structure; 🔒/⏸️ tier markers |
| **Substantial-equivalence / predicate** | Comparative, even | New-vs-predicate **table**; differences stated plainly and shown **not** to raise different questions of safety/effectiveness — never minimized, never hidden | **D14.2** (SE tone), D14.3 (predicate-selection rationale + disclose/mitigate factor failures), R3 (claim ↔ evidence) | **Act:** em-dash density; puffery around the equivalence claim. **Ignore:** comparison-table structure |
| **PCCP summary / Modification Protocol** | Committed, bounded | Change categories + the Modification Protocol structure + performance criteria + routing; template-altitude thresholds marked `[locked at design transfer]` | **D14.1** (PCCP boundary — architecture docs carry ≤1 PCCP cross-ref), R2 (protocol steps have acceptance criteria), D10 (managed TBDs) | **Act:** em-dash density. **Ignore:** category/step `**Bold:**` lists |
| **Architecture / SAD** | Descriptive, structural | Module map, boundaries, data flows, classification tables, interfaces; parent-system vs child-item scope | R1, D8 (title-based citation — no repo paths), W12.1, W7 (parallel tables) | **Act:** em-dash density (tends to inherit essayistic drafting). **Ignore:** architecture tables; module `**Bold:**` lists |
| **Requirements (SRS/SRD)** | Prescriptive | One requirement = one **testable behavior + acceptance criterion**; identified + traceable | **R2** (requirement form), **W10** (shall/should/may; no "will"), D9 (trace to controlled artifacts) | **Act:** hedges inside a requirement (a requirement must be crisp). **Ignore:** the `REQ-N:`/`**Bold:**` itemization |
| **Design (SDS/SDD)** | Descriptive | Design outputs tracing to requirements; how, at implementation altitude | R3 (design ↔ requirement/verification), R1, D12 | **Act:** em-dash density. **Ignore:** design-element lists/tables |
| **Risk (SRA / hazard analysis / FMEA)** | Analytic, chained | ISO 14971 chain — hazard → sequence of events → hazardous situation → harm; ratings at the **cause** layer, not the hazard | **R9** (never re-voice an unevidenced property as confident prose; keep requirements), R3, R4 (rationale = claim → basis → consequence) | **Act:** puffery/over-claiming a control's effectiveness. **Ignore:** the chain/`**Bold:**`/table structure — it *is* the method |
| **V&V protocol / report** | Procedural | Test case → the requirement it verifies → method → acceptance criterion → result | R2/R3 (test ↔ requirement trace), D3 (control header), W7 | **Act:** em-dash density in narrative sections. **Ignore:** step lists, results tables |
| **Cybersecurity scope brief** | Scope handoff | *What* is committed for the 510(k), at scope altitude — not the full evidence set; §524B framing | R1.3 (commit obligations, don't recite the guidance), D14 (FDA framing) | **Act:** em-dash density (this doctype tends to run highest). **Ignore:** the four-view / `**Bold:**` structure |

## The through-line on the slop pass (why the last column matters)

A general-prose AI-slop detector (`writing-well` `slop`) is tuned for essays and blog posts. On a **regulated** document, exactly one of its signals transfers cleanly across every doctype — **em-dash density** — because converting an em-dash to a period/colon/comma is register-neutral: it never changes a claim, and heavy em-dash use is a genuine "reads AI-generated" tell a reviewer will notice. The detector's **`aitell-listformat`** (`**Bold:**` colon-lists) and **`aitell-emoji`** (🔒/⏸️ tier markers) hits are **false positives for the regulated register** in nearly every doctype above: bounded `**Bold:**` itemization is the *legitimate, scannable* structure regulators expect for requirements, categories, and hazard chains, and the tier-marker emoji are stripped by the package assembler before transmission. Acting on those two would **damage** the document. Two doctypes are stricter than the rest: the **IFU** (a legal string — keep it plain, no flourishes at all) and **requirements** (a hedge inside a `shall` statement is a real defect, not just style).

## Interaction with the standard

- These notes **layer on** `authoring-standard.md` — they never override a W/R/D rule; they say which rules dominate for a doctype and how to read the supplementary prose passes.
- For the **structural** contract of a specific doctype (columns, sign-off rows, mandatory sections), the governing QMS FORM/SOP named in the doctype's `.taxonomy.yml` `governing_qms` block is authoritative (see the `doctype-governance` rule) — this file is register/form *guidance*, not the FORM schema.
