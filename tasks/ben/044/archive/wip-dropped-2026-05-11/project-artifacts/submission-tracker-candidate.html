What is Q-Sub Cover Letter?

Formal cover letter that opens the PP3500 Pre-Submission package. Identifies the submission type (Pre-Submission), sponsor (GlobalLogic), the device (PainEase PCA Advanced / PP3500), the primary regulatory contact, and the purpose of the Q-Sub. Frames the document set FDA reviewers will encounter and signposts where the specific questions live.

Why it matters in this project

PP3500 is filed as a 510(k) with PCCP (target K210345) using PP3000 (K190567) as predicate. The Q-Sub is the team's first formal interaction with FDA on this program — a clean cover letter is what makes the package look like a credible Q-Sub rather than a half-formed 510(k). The letter also tells FDA whether a meeting is requested (we should request one given the criticality carve-out + PCCP scope are novel) so reviewers know which staff to assign before opening the questions document.

Main topics

  • Submission type and program track: Explicit Pre-Submission designation; references FDA Q-Submission Program guidance §V.A.
  • Sponsor and device identification: GlobalLogic, contact name + email + phone, PP3500 device name, intended product code (LZH for PCA pump), classification (Class II).
  • Predicate and pathway framing: Predicate PP3000 (K190567), pathway 510(k) + PCCP, expected K-number K210345.
  • Purpose statement: One paragraph: validate predicate adequacy, PCCP envelope, criticality carve-out, MFD scoping with FDA before formal filing.
  • Meeting request and format: Whether teleconference, in-person, or written-feedback-only is requested; proposed timing window.
  • Document inventory: Brief list of what FDA will find in the package (Questions, Agenda, Device Description, Predicate Identification, supporting drafts).
Regulatory anchors: FDA Guidance — Requests for Feedback and Meetings for Medical Device Submissions: The Q-Submission Program (2023) §V.A · 21 CFR 807.81 — 510(k) general procedures (program context) (supporting)

What is Pre-Submission Questions for FDA?

The substantive payload of the Q-Sub. Contains explicit, numbered questions the team wants FDA to answer before formal 510(k) filing — targeted, focused, and directly answerable rather than open-ended discussion prompts. Each question is scoped to a single decision and references the supporting materials elsewhere in the package.

Why it matters in this project

For PP3500, the Q-Sub questions are the team's opportunity to de-risk the four highest-stakes regulatory decisions before filing K210345: (1) is PP3000 (K190567) an adequate predicate given the SaMD additions and connectivity expansion; (2) is the proposed PCCP envelope (drug library updates, firmware patches, predictive alarms within fixed risk profile) acceptable as scoped; (3) does the criticality carve-out (Ct*-tagged requirement subset for filing scope, deferred non-Ct* items for commercial-only V&V) align with FDA expectations for a Class II infusion pump; (4) how should the SaMD/SiMD/hardware combination be scoped under the Multiple Function Device guidance. Sharp questions here save weeks of post-filing back-and-forth.

Main topics

  • Predicate adequacy (Q-1): Is PP3000 (K190567) an adequate predicate given the new SaMD components, connectivity adapter, and AI-assisted predictive alarms in PP3500?
  • PCCP envelope acceptability (Q-2): Does the proposed change protocol scope (drug library updates, firmware patches, predictive-alarm SaMD changes within the cleared risk profile) qualify under the FDA PCCP final guidance?
  • Criticality carve-out approach (Q-3): Is the Ct*-tagged design-input subset (CtS/CtF/CtC/CtP) an acceptable basis for splitting the 510(k)+PCCP filing scope from the commercial-only V&V track?
  • MFD scoping (Q-4): How should the SaMD UI / SiMD pump firmware / custom medical electrical hardware combination be analyzed under FDA Multiple Function Device guidance (2020)?
  • Cybersecurity expectations (Q-5): Confirm the team's §524B compliance approach (SBOM, threat model, vulnerability management, secure release) is aligned with FDA 2023 cybersecurity guidance for a connected infusion pump.
  • Software documentation level (Q-6): Confirm Enhanced Documentation Level per FDA Software Premarket Submissions guidance (June 2023) given Class C SiMD pump firmware and Class B/C SaMD components.
  • Cross-reference index: Each question cites the supporting draft material in the Q-Sub package (System SAD, Design Inputs, Cybersecurity Plan, Clinical Evaluation Plan).
Regulatory anchors: FDA Guidance — Requests for Feedback and Meetings for Medical Device Submissions: The Q-Submission Program (2023) §V.B · FDA Guidance — Predetermined Change Control Plans for Medical Device Software (Final, Sept 2023; FD&C §515C) · FDA Guidance — The 510(k) Program: Evaluating Substantial Equivalence (2014) · FDA Guidance — Multiple Function Device Products (2020) · FDA Guidance — Cybersecurity in Medical Devices: Quality System Considerations and Premarket Submissions (Sept 2023; §524B) (supporting) · FDA Guidance — Content of Premarket Submissions for Device Software Functions (June 2023) (supporting)

What is Pre-Submission Meeting Agenda?

Proposed agenda for the Pre-Submission meeting (teleconference or in-person). Lists the topics the sponsor wants to walk through with FDA, the proposed time allocation per topic, the sponsor attendees with their roles, and the order of discussion. Sent in advance so FDA reviewers can prepare and bring the right specialists.

Why it matters in this project

For the PP3500 Q-Sub, an interactive meeting is the highest-leverage outcome — the questions span four distinct domains (predicate, PCCP, carve-out, MFD) and each pulls in a different FDA reviewer specialty (510(k) reviewer, software reviewer, cybersecurity reviewer, AI/ML CDRH staff). A clear agenda gets the right people in the room. Without it, the meeting devolves into one reviewer answering all questions with reduced confidence on the cross-domain topics.

Main topics

  • Meeting logistics: Date/time window, format (teleconference / in-person / hybrid), expected duration (typical Pre-Sub: 60–90 min).
  • Sponsor attendees + roles: RA lead, R&D lead, Software lead, Cybersecurity lead, Clinical lead — names + titles.
  • Topic-by-topic time allocation: Per Q-Sub question (Q-1 predicate, Q-2 PCCP, Q-3 carve-out, Q-4 MFD, Q-5 cyber, Q-6 software docs) with proposed minutes.
  • Order of discussion: Sequenced so foundational topics (predicate) precede dependent topics (PCCP envelope assumes predicate is settled).
  • Pre-read pointers: For each topic: which supporting draft in the package the discussion will reference (System SAD, Cybersecurity Plan, etc.).
  • Out-of-scope / parking-lot: Topics the sponsor explicitly does NOT want to discuss in this Q-Sub (defer to filing-time review).
Regulatory anchors: FDA Guidance — Requests for Feedback and Meetings for Medical Device Submissions: The Q-Submission Program (2023) §V.C

What is Device Description (Q-Sub level)?

Concise device description sufficient to ground the Pre-Submission questions. Lighter than the 510(k) Section 5/6 device description — covers intended use, indications for use, principal technological characteristics, and a high-level comparison framing vs the predicate. The goal is to give FDA reviewers enough context to engage substantively with the questions without expecting filing-level depth.

Why it matters in this project

The Q-Sub questions for PP3500 (predicate adequacy, PCCP envelope, MFD scoping) are unanswerable without FDA understanding the device — but a full 510(k) device description is overkill for a pre-submission. This Q-Sub-level version focuses on what makes PP3500 different from PP3000 (the predicate): (a) the addition of SaMD components and connectivity adapter, (b) AI-assisted predictive alarms within the PCCP envelope, (c) §524B cybersecurity posture (PP3000 pre-dates §524B), (d) the Ct*-tagged criticality carve-out approach. These deltas are the reason the questions matter.

Main topics

  • Intended use: IV PCA delivery for opioid/non-opioid analgesics in supervised acute-care settings, adults/adolescents ≥12y/≥40kg.
  • Indications for use: Hospital ward, PACU, ambulatory; explicit exclusions (intrathecal, epidural, arterial, MRI environments, unsupervised home use).
  • Principal technological characteristics: SaMD UI + SiMD pump firmware + custom medical electrical hardware combination; connectivity adapter; drug-library architecture; alarm system.
  • Predicate framing — PP3000 (K190567): Same intended use and primary indications; deltas in SaMD scope, AI-assisted alarms, cybersecurity posture, MFD profile.
  • PCCP-relevant features: Drug library content updates, firmware patches against fixed risk profile, predictive-alarm SaMD changes — features the PCCP envelope is designed to govern.
  • High-level architecture diagram pointer: References the draft System SAD elsewhere in the package for architectural detail; this section stays at description level.
Regulatory anchors: FDA Guidance — Requests for Feedback and Meetings for Medical Device Submissions: The Q-Submission Program (2023) §V.D · 21 CFR 807.92(a)(4)–(5) — 510(k) Summary device description (analog reference) (supporting)

What is Predicate Identification (PP3000 / K190567)?

Identifies PP3000 (K190567) as the predicate device for the planned PP3500 510(k) with rationale for the predicate selection. Lighter than the full 510(k) Section 12 predicate comparison — establishes that PP3000 is the right anchor, but defers the detailed feature-by-feature comparison table to filing time. This Q-Sub-level version provides enough basis for FDA to engage on Q-1 (predicate adequacy).

Why it matters in this project

Predicate selection is the single highest-stakes decision in a 510(k) substantial-equivalence pathway. If FDA disagrees with the choice of PP3000 at filing time, the team has wasted months. Validating PP3000 as predicate at the Q-Sub stage — specifically getting FDA comfortable that PP3500's SaMD / connectivity / AI-alarm additions don't disqualify PP3000 — is the most valuable Q-Sub outcome. This document tees up that question with sufficient predicate context (clearance number, product code, indications, key technological characteristics) without bogging down in the full SE table.

Main topics

  • Predicate device identification: PP3000 (K190567) — sponsor, clearance date, product code (LZH PCA pump, Class II).
  • Predicate intended use and indications: Verbatim statements as cleared, used as the SE anchor for PP3500.
  • Principal technological characteristics — predicate: PP3000's pump mechanism, alarm system, drug-library approach, UI architecture as cleared.
  • Subject device deltas (preview): High-level enumeration of how PP3500 differs from PP3000 (pointer to detailed comparison at filing time).
  • Predicate-selection rationale: Why PP3000 vs other PCA pumps (B Braun Outlook, ICU Medical LifeCare, etc.) — same product code, same intended use, closest technological match, manufacturer continuity.
  • Reference devices (if any): Any reference devices being cited for technological precedent (e.g., for the AI-assisted alarm pattern, the connectivity adapter approach).
Regulatory anchors: FDA Guidance — The 510(k) Program: Evaluating Substantial Equivalence (2014) §IV Predicate Selection · 21 CFR 807.87(g) — Predicate device information requirement · 21 CFR 807.92(a)(3) — Predicate identification in 510(k) Summary (supporting)

What is Cybersecurity Plan — pca-device?

Plan governing the secure-development activities, threat modeling, SBOM management, vulnerability disclosure, and post-market vulnerability response for the PP3500 PCA pump.

Why it matters in this project

PP3500 is a connected infusion pump and therefore a 'cyber device' under FD&C §524B — without a cybersecurity plan, SBOM, and vulnerability-response commitment, the 510(k) is refuse-to-accept; this also differentiates PP3500 from the PP3000 predicate, which pre-dated 524B obligations.

Main topics

  • Secure development lifecycle: IEC 81001-5-1 SDL activities mapped onto the SDP.
  • Threat modeling & risk assessment: STRIDE / equivalent on the pump/wireless/cloud attack surfaces.
  • SBOM management: Generation, format, refresh cadence, and submission with the 510(k).
  • Vulnerability handling & coordinated disclosure: Intake, triage, patching SLAs, and stakeholder communication.
  • Post-market monitoring & PCCP linkage: How patch releases flow through the PCCP envelope and FDA reporting.
Regulatory anchors: FD&C Act §524B (Cyber Device requirements) · FDA Guidance: Cybersecurity in Medical Devices — Quality System Considerations and Premarket Submissions (Sept 2023) · IEC 81001-5-1:2021 §5 · AAMI TIR57 · 21 CFR 820.30

What is Design Inputs — PainEase PCA Advanced (PP3500)?

The substantive design-inputs (system requirements) document for PP3500 — translates validated user needs into testable system requirements with Ct* criticality tags, acceptance criteria, and verification methods.

Why it matters in this project

Anchors PP3500's substantial-equivalence story against PP3000 (K190567): each design input maps to a predicate analog or to a delta the 510(k) must justify, and the Ct* tagging determines which requirements live inside the K210345 filing scope vs the LMR1/LMR2 commercial track.

Main topics

  • Intended use & indications: Adult/adolescent IV PCA for analgesics in supervised acute-care settings; contraindications enumerated.
  • Functional requirements: Continuous basal + patient-activated bolus delivery within prescriber-defined limits.
  • Safety requirements (CtS): Occlusion detection, air-in-line, dose limits, alarm priorities per IEC 60601-1-8 and IEC 60601-2-24.
  • Software & cybersecurity requirements: Per IEC 62304 SDLC and IEC 81001-5-1 §5.2 security requirements supporting 524B.
  • User-need traceability: Each requirement traces upstream to DHF-PP3500-UN-001 user needs and downstream to verification.
  • Standards conformance hooks: Maps to IEC 60601-1, 60601-1-2 EMC, 60601-2-24, IEC 62366-1 usability, ISO 14971 risk, ISO 10993-1 biocompat.

What is PCA Device — System Software Architecture Description (SAD)?

The System Software Architecture Description (SAD) defines the on-device software architecture of the PP3500 PCA pump — SaMD clinician/patient UI, SiMD pump firmware (RTOS), and the electromechanical hardware boundary — including trust boundaries with the off-device Connectivity Adapter and Cloud Suite.

Why it matters in this project

The SAD is the structural anchor for the PP3500's K210345 510(k)+PCCP filing: it locks the 'PCA Device Alone' filing scope, defines the Adapter trust boundary that scopes cybersecurity claims, and underpins substantial-equivalence argumentation against predicate PP3000 (K190567) by showing where PP3500 architecturally deviates and where it inherits.

Main topics

  • Composition & filing scope: SaMD + SiMD + custom medical electrical hardware combination; PCA-Device-Alone scope per regulatory strategy.
  • Trust boundary & cybersecurity architecture: Adapter treated as untrusted; TLS 1.3 mutual auth, local authentication of inbound payloads — supports FDA Cybersecurity Guidance §V.
  • MFD impact: Multiple-Function Device decomposition and impact analysis for SaMD UI vs SiMD pump-control functions per FDA MFD Guidance.
  • IEC 62304 software item decomposition: Class B/C SaMD modules and Class C pump firmware items mapped to architectural elements.
  • Predicate architectural delta: Architectural differences vs PP3000 (K190567) that drive substantial-equivalence and PCCP envelope definition.
  • Secure development lifecycle alignment: Architecture artifacts that satisfy IEC 81001-5-1 §5.3 secure-by-design requirements.
Regulatory anchors: FDA Cybersecurity Guidance (2023) §V Security Architecture · FDA Multiple Function Device Guidance (2020) §IV–V · IEC 81001-5-1:2021 §5.3 Software architecture · IEC 62304:2006+A1:2015 §5.3 Software architectural design · 21 CFR 807.87 — 510(k) content requirements
