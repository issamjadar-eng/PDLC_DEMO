<!-- STRATEGY CONTENT: development, hygiene, audit-closure -->

**Strategy — Hygiene-first pass after a Required-severity audit.**

Principle: When a skill-registry pull lands and `/best-practices` surfaces a tranche of pre-existing Required FAILs that were previously Recommended (severity escalation), close them in one dedicated fix pass under the sync task rather than spreading them across the specific feature tasks that would otherwise own those surfaces.

Why: The escalation source is a single skill-version bump (e.g., medtech-docs v14 → v17 promoting conventions/README-every-folder to Required). Fanning the fix across N feature tasks creates bookkeeping overhead and produces N task-level changelog entries for what is really one root cause. Closing them under the sync task keeps the motivation discoverable ("why does 261 README stubs have a Conventions section added on 2026-04-20?" → task 018, traceable to the skill bump) and leaves feature-task scope clean.

How to apply: Use this pattern when (a) audit FAILs are distributed across many files but share a single skill-version cause, (b) the fix is mechanical (template insert, stub creation) rather than content-authoring, and (c) severity is Required so deferral pushes the FAIL into the next audit. Do NOT use this pattern when the audit FAIL is actually a design-decision surface (e.g., "every User Need traces to a measurable acceptance criterion") — those belong in the feature task because the fix is reasoning, not template.

<!-- LESSONS LEARNED: audit, skill-registry, convention-sweep -->

**Lesson — Bulk conventions sweeps beat per-file editing when 180+ files all miss the same section.**

Why: First instinct was to delegate 180 per-file README edits to parallel subagents. A scripted Python pass that inserts a generic Conventions block before `## Changelog` completed the same work in one call, was deterministic, auditable via git diff, and left room to re-author specific folders' conventions later where the generic block is too thin.

How to apply: When `/best-practices` surfaces N>20 files missing the same structural section, write a small Python pass rather than fan-out. Only fan-out to subagents when the fix requires per-file reasoning (content decisions, not template inserts). The generic block should be technically correct but minimal — a placeholder acceptable to the audit, not a substitute for the real thing.
