Our Difference

Most “agentic” MedTech is a wrapper.
Ours is a purpose-built harness.

WHAT VENDORS SHIP
Context and a UI wrapped around someone else’s model.
1 · Code-completion rebranded

Copilot, Cursor, Codeium with a vendor wrapper. Productive on the keystroke — blind to everything else. No idea your work product needs IEC 62304 traceability, that an audit trail must name a human, or that an output is going into a 510(k).

2 · Chatbot on a data lake

RAG over your docs. No provenance from answer to source — you can’t tell which document fragment shaped the response. Embeddings shift on every rebuild; data ages silently. Same question, different answer next month. No full-context grounding — just whatever the nearest-neighbor lookup returns.

3 · Hosted autonomous-agent studio

A closed-box agent running in someone else’s cloud. The audit trail is theirs, not yours. Not purpose-built for MedTech — no IEC 62304, ISO 14971, or DHF grounding. Not portable — change vendors and both the capability and your history walk away.

WHAT WE BUILT
A purpose-built MedTech agentic harness — versioned, audited, and yours.
  • Domain-grounded. IEC 62304, ISO 14971, and ISO 13485 encoded directly into skills, agents, hooks, and rules — with a Part 11-aware publishing flow into the formal review system.
  • Audit-trailed by construction. Every decision attributable; every change links design inputs to verification to the DHF record.
  • Lives in your repository. Versioned alongside the device. No vendor tenant. No platform you have to log into.
  • Built for regulated delivery. DHF-shaped outputs, submission-ready by construction, reusable across programs in your portfolio.

The Defense-in-Depth

Six layers of guardrails. Not one.

In an unregulated context, a single L1 gate is often enough. In HCLS, any single layer's failure means the entire compliance posture collapses. Multi-model substrate is part of the layered defense — adversarial validation requires different models checking each other.

Pre-action gates
Block before the action. Task gate · freeze gate.
L2

CLAUDE.md rules · [VERIFY] · default-to-action.
L3
In-flight verification

L4
Post-action checks

L5

L6
Continuous improvement

Hooks — automatic tripwires you can't forget to run

A hook is a small automation that fires at a specific moment — when a session starts, when a file is about to be edited, when work is about to end — and either allows, blocks, or adds context to the action. Hooks are invisible until one trips. When one trips, it means the system caught an issue before it became a problem.

HookWhen it firesWhat it prevents
Task-first gate (check-active-task.sh)Before any file editRefuses to edit a file unless there's an active task document that owns the change. No orphan edits, ever.
Session security check (security-assert.sh)When a session opensRuns the project-secops audit against project.yml allowlists. High-severity drift triggers guided remediation.
Morning briefing (session-briefing.sh)When a session opensMissing context — a 12h-throttled digest of what changed across the team since you last looked.
Checkpoint recovery (checkpoint-recover.sh + session-cleanup.sh)Session start + endLost project narrative — a session that ends without a /checkpoint leaves a marker, and the next session offers recovery from git history.

Skill integrity watch (skill-creator-watch.py)Before edits under .claude/skills/Uncontrolled changes to the shared skill surface — skill edits follow the skill-creator conventions.
Taxonomy freshness (taxonomy-freshness.sh)When a session opensSilently stale doctype-governance mappings — flags .taxonomy.yml files past their review cadence.

A rule is a short written convention stored in CLAUDE.md or .claude/rules/ that the AI assistant reads before acting. Rules are how we encode agreements like "every folder under docs/ must have a README" or "every README has a ## Conventions and a ## Changelog section" — and then the assistant actually follows them, every time, without being reminded.
